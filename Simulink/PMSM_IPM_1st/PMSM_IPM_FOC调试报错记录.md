# PMSM_IPM_FOC 调试报错记录

> 记录对象：`PMSM_Model.slx`（表贴式 PMSM 矢量控制系统，目标 i_d = 0、i_q = 1 A）
> 环境：MATLAB R2022b / Simulink 10.6 / Simscape Electrical 7.8
> 说明：每条记录都注明了**判定依据**（实测波形、参数值或离线校验结果），
> 便于日后复查；问题 4，5，6，8为AI系统排查，问题11为AI排查，但并不存在实际问题。

---

## 问题1：逆变器输出为 0

**现象**：Half-Bridge 输出电压恒为 0。

**原因**：Threshold voltage 设成了 6V，而 PWM 信号是 0/1 逻辑电平。

**解决**：把 Threshold voltage 改成 0.5V。

**教训**：Ideal Switch 的阈值电压必须匹配驱动信号的电平。

> 补充：本模型里阈值参数随器件类型变化——
> `device_type = MOSFET` 时用 `mosfet_Vth`（当前值 0.5 V），
> `device_type = GTO` 时用 `gto_Vgt`（默认 6 V）。
> **换器件类型时一定要回头检查阈值**，否则门极信号永远达不到开通条件。

## 问题2：id/iq 剧烈震荡

**现象**：切换到闭环后，id/iq 在 ±100A 震荡。

**原因**：开环 Ramp 角度和 Sensor 角度切换时没有对齐。

**解决**：让 Ramp 的初始值等于 Sensor 的初始角度，切换瞬间不跳变。

**教训**：开环切闭环时，角度必须连续，否则 Park 变换会错乱。

> 补充：判断"切换瞬间角度是否连续"的定量方法——
> 把 `Ramp` 值和 `6×θ_mech` 画在同一张图上，读切换时刻两个值的差；
> 或者直接算 `mod(θ_ramp − 6θ_mech, 2π)`，这个量在整个切换窗口内应当接近常数且接近 0。

## 问题3：切换逻辑接反 —— 0.1 s 后控制角变成了自由运行的斜坡

**现象**：整个 0.5 s 内 i_d 在 −118 … +116 A 之间振荡，i_q 在 −119 … +120 A 之间振荡；
V_d / V_q 长期顶在 ±57 V 限幅上；电机转速失控上升，闭环完全不起作用。

**原因**：`Open_Start` 子系统的角度选择逻辑接反了。
`Relational Operator3` 的算子是 `Clock > 0.1`，它的输出接到 `Switch` 的控制端
（判据是 `u2 > 0.5` 时选 u1 = Ramp），于是：

| 时间段 | theta 实际取的值 |
|---|---|
| 0 ~ 0.1 s | `6 × θ_mech`（编码器角度，闭环） |
| 0.1 s 之后 | `2π × 10 × t`（**自由运行的开环斜坡**） |

**判定依据**：实测 t = 0.1 s 时 `theta_log` 和 `gain_log` 都等于 −14.240448 rad，
说明此刻取的是 `6θ_mech`；而斜坡值为 `2π×10×0.1 = 6.2832 rad`。
原始跳变 20.52 rad，折算到电角度周期上相当于 **96°** —— 控制坐标系瞬间转错近 90°，
之后控制角与转子位置完全无关。

**解决**：把 `Relational Operator3` 的算子改为 `<=`，
并把 `Constant2` 由 `0.1` 改为 `-1`，使**全程使用编码器角度**。

> 为什么不保留"开环起动"：该电机 `J = 1e-4`、`iq = 1 A` 时机械角加速度约 900 rad/s²，
> 而斜坡只有 `2π×10 rad/s`（10 Hz 电气），转子会瞬间冲出同步区失步。
> 有真实位置传感器时，**直接闭环起动才是正确做法**。

**教训**：遇到"控制器调不动"，**第一件事是确认反馈量真的是被控对象的真实状态**。
做法是把反馈信号和一路"独立测量的真值"画在同一张图上对比——
本次就是把模型的 θ 与 `simlog.PMSM` 里的转子角对比，一眼看出跳变。

## 问题4：PI 只有比例作用，积分器根本没有记忆

**现象**：即使角度正确，i_d / i_q 也收敛不到给定值，存在稳态静差，抗扰能力几乎为零。

**原因**：`Vd` / `Vq` 两个 MATLAB Function 的**第一句都是 `integral = 0;`**。
`integral` 是普通局部变量，每次调用都被清零，积分器完全没有记忆。
实际输出退化成
```
Vd = Kp·error + Ki·Ts·error ≈ Kp·error      （Ts = 1e-4，第二项只有第一项的 1%）
```

**判定依据**：原模型 `Kp = 10`、`Ki = 100`。t = 1e-4 s 时实测 `Vq = 10.01 V`，
恰好等于 `Kp × error = 10 × 1`，证明积分项只贡献了 0.01 V。

**解决**：把 `integral` 声明为 `persistent`，改成真正的离散 PI：

```matlab
function Vd = fcn(Kp,Ki,error)
    persistent integral
    Ts    = 1e-4;
    limit = 57;
    if isempty(integral)
        integral = 0;
    end
    integral = integral + error*Ts;
    ...
```

**教训**：写数字控制器时，**凡是要"记忆"的量都必须显式声明为 `persistent`**。
验证方法：给控制器一个阶跃输入，看输出是不是"斜坡形状"；
如果输出和输入形状相同，积分就没生效。

## 问题5：抗饱和钳位钳错了对象，等于没有限幅

**现象**：控制器一旦饱和就很难退出来；电压输出长时间顶在限幅值上。

**原因**：原代码写的是
```matlab
if integral > limit, integral = limit; end      % limit = 57
```
被限的是 `integral` 本身（量纲是 A·s），但它对输出的贡献是 **`Ki × integral`**。
Ki = 1000 时贡献量可达 ±57000 V，而母线才 100 V —— 这个限幅毫无作用。

**解决**：把限幅施加在真正的贡献量上：
```matlab
if Ki ~= 0
    if Ki*integral >  limit, integral =  limit/Ki; end
    if Ki*integral < -limit, integral = -limit/Ki; end
end
```
或者用反算法抗饱和（back-calculation）：
```matlab
V = Kp*error + Ki*integral;
if V > limit
    V = limit;
    integral = (V - Kp*error)/Ki;    % 把超出的部分从积分器里扣回去
end
```

**教训**：**限幅一定要作用在物理量纲正确的节点上**。
写完之后回算一下："这个量被钳到 57，它在输出端对应多少伏？"——一算就发现问题。

## 问题6：代码里写死 Ts，图表却是连续执行 —— 等效增益被放大两个数量级

**现象**：模型能编译、能仿真，不报任何错，但电流环的实际等效增益与整定值对不上，
按零极点对消算出来的 Kp/Ki 完全失效。

**原因**：模型里 8 个 MATLAB Function 图表的属性全部是
`ChartUpdate = 'INHERITED'`、`SampleTime = '-1'`，即**连续采样**。
在变步长求解器（ode23t）下，图表会在**每个 minor step** 执行一次
（实测 theta 通道有 533003 个采样点/0.5 s，约 1e6 次/秒），
而代码里的积分增量写的是固定 `Ts = 1e-4`，于是
**积分量被重复累加了约 100 倍**，等效 Ki 被放大两个数量级。

**判定依据**：用 `sfroot` 读图表属性得到 `ChartUpdate = INHERITED`；
编译后 `CompiledSampleTime = [-1 0]`（-1 表示继承/连续）。

**解决**：给 6 个控制图表显式设置离散采样时间：
```matlab
rt  = sfroot;
chs = rt.find('-isa','Stateflow.EMChart');
ch  = chs(7);                        % 找到 Vd / Vq 图表
ch.ChartUpdate = 'DISCRETE';
ch.SampleTime  = '1e-4';
```
同时把 `Delay` / `Delay1` / `Delay2` 的采样时间统一为 `1e-4`，
使整个控制器成为一套规整的 10 kHz 数字控制器。

**教训**：**代码里写死了 Ts，图表就必须以同一个 Ts 离散执行**。
两者不一致时编译和仿真都不会报错，但增益是错的 ——
这类"静默错误"比语法错误难查得多。判断口诀：
**"有 persistent 的图表，必须有 SampleTime"**。

## 问题7：SVPWM 扇区公式手滑，合成电压与指令值差 110 V

**现象**：闭环一上电就发散。离线校验 SVPWM 时，由占空比反算出的 αβ 电压
与指令电压**最大相差 110 V**（母线电压才 100 V）。

**原因**：扇区公式打错了一个括号：
```matlab
Num_sector = floor((pi*angel)/3) + 1;      % 原代码（错）
Num_sector = floor(angel/(pi/3)) + 1;      % 正确
```
`(π·angel)/3` 与 `angel/(π/3)` 相差一个 `(π/3)² ≈ 1.097` 的因子，
导致扇区边界从正确的 60°/120°/180°… 偏移到 54.7°/109.5°/164.2°…，
**约 9% 的电气角度会落进错误扇区**，此时 `θ' = angel − (sector−1)·π/3` 变成负数，
`T2 = √3·Ts·V/Vdc·sin(θ')` 随之变负，占空比映射整体错位。

**解决**：改为 `floor(angel/(pi/3)) + 1`。

**判定依据（离线交叉校验）**：用"min/max 共模注入法"（另一种完全不同的 SVPWM 实现）
反算期望占空比，再对比两种实现合成的 αβ 电压，扫 288 组（角度 × 幅值）：

| 实现 | 最大误差 |
|---|---|
| 原扇区公式 + 原映射表 | **110.0 V** |
| 修正后 | 3.6e-14 V |

**教训**：这类"公式没错、打字错了"的 bug 最难查。
**解法是建一套独立的验证手段** —— 不要用同一种思路验证自己。
养成"用第二种方法验证第一种方法"的习惯，是从学生到工程师的关键差别。

## 问题8：扇区改对了，占空比映射表还是错的

**现象**：修正扇区公式后，合成的电压矢量仍然与指令值相差极大（见问题 7 的校验表，
单改扇区并不能把误差降到零）。

**原因**：`svpwm_duty` 里的 `switch sector` 表是从资料上抄来的 TI 表，
但那套表对应的是**另一套扇区编号定义**。用可手算的特例验证：
指令矢量在 90°（扇区 2）时，`Ta = 0.4134`、`T1 = T2 = 0.0866`，正确结果应为

```
Da = 0.5,  Db = 0.5866,  Dc = 0.4134
```

而原表（case 2: `Da = Ta, Db = Tc, Dc = Tb`）给出

```
Da = 0.4134,  Db = 0.5866,  Dc = 0.5        ← A 相和 C 相互换了
```

**解决**：换成逐扇区推导并验证过的表（`Ta = (Ts−T1−T2)/2`）：

| sector | Da | Db | Dc |
|---|---|---|---|
| 1 | Ta+T1+T2 | Ta+T2 | Ta |
| 2 | Ta+T1 | Ta+T1+T2 | Ta |
| 3 | Ta | Ta+T1+T2 | Ta+T2 |
| 4 | Ta | Ta+T1 | Ta+T1+T2 |
| 5 | Ta+T2 | Ta | Ta+T1+T2 |
| 6 | Ta+T1+T2 | Ta | Ta+T1 |

并在末尾加钳位 `Da = min(max(Da,0),Ts)` 等，防止过调制时出现负占空比。

**教训**：**抄任何算法表 / 系数表，必须先用一个可手算的特例验证**。
抄表不难，难的是确认前提条件 —— 这里就是"扇区编号的定义"。

## 问题9：控制频率和开关频率不匹配，电流环带宽被浪费 10 倍

**现象**：电流环的采样时间是 1e-4 s（10 kHz），PI 里也硬编码 `Ts = 1e-4`，
但三角载波只有 1 kHz；电流环带宽上不去，电流纹波偏大。

**原因**：`Triangle Generator` 的 mask 参数 `Freq = 1e3`（**实测值**），
而 `Delay` / `Delay1` / `Delay2` 的 `SampleTime = 1e-4`。
控制算法每 100 µs 算一次，功率级每 1 ms 才响应一次，
控制带宽被严重浪费；开关损耗与电流纹波也都不在合理工作点。

**判定依据**：`get_param('.../Triangle Generator','Freq')` 返回 `1e3`；
Delay 的 `SampleTime` 返回 `1e-4`。

**解决**：载波频率改为 **10 kHz**，与电流环同频：
```matlab
set_param([m '/Triangle Generator'], 'Freq', '1e4');
```
改完后实测载波频率 10000.0 Hz，载波波形 0~1 正常。

**教训**：数字控制系统的三个频率必须**成组设计**：

```
开关频率 fsw  ≥  采样频率 fs  ≥  控制带宽 fc × 10
```
本模型最终取 `fsw = fs = 10 kHz`，`fc ≈ 318 Hz`，余量充足。

## 问题10：id/iq 示波器"完美"，但电机一步都不转（3π/2 角度补偿陷阱）

**现象**：启用 θ 通道上那个被注释掉的 `Bias` 块（值 `3*pi/2`）之后，
i_d 均值 −0.0000 A、i_q 均值 +1.0000 A —— **比不启用时还"准"**；
但电机转速 **0.0 rpm**，完全不转。

**判定依据（对照实验，其余条件完全相同，仿真 0.2 s）**：

| Bias = 3π/2 | i_d 平均 | i_q 平均 | 转速（0.2 s） |
|---|---|---|---|
| 注释掉（正确） | +0.0022 A | +0.9975 A | **729.9 rpm** |
| **启用（错误）** | −0.0000 A | +1.0000 A | **0.0 rpm** |

**原因**：`3π/2 ≡ −π/2`，相当于把控制坐标系相对转子 d 轴转了 90°。
因为 **Park 测量和反 Park 输出用的是同一个角度**，
示波器上的 i_d / i_q 依然显示 0 和 1，但电流实际上全部落在转子真实 d 轴上 ——
表贴式电机 d 轴不产生转矩，于是电机不转。

**解决**：`Bias` 保持注释状态（`Commented = through`），θ 直接用 `6 × θ_mech`。
用**独立信息源**确认角度约定：把模型的 Park 输出与 PMSM 模块内部记录的
`i_d` / `i_q`（`simlog.PMSM.i_d`）逐点对比：

```
   t        id(模型)   iq(模型)    id(模块)   iq(模块)
 0.09662     69.73     -22.53      68.74      -25.39
 0.09829     55.64     -71.43      56.42      -70.81
 0.09996     97.27     -11.04      97.87       -2.24
```

两者几乎完全重合 → 说明 `6 × θ_mech` 本来就是对的，不需要任何偏移
（模块的 `axes_param = ee.enum.rotorangle.daxis`，即"a 相轴到 d 轴的夹角"，
与模型的 Clarke/Park 约定本来就一致）。

**教训（本条最重要）**：
> **判断 FOC 是否正常，绝对不能只看 i_d / i_q 波形，必须同时确认转矩/转速有没有出来。**
>
> 当同一个角度同时用于测量和输出时，**任意常数角度偏差都不会反映在 i_d/i_q 上**，
> 只会降低效率甚至完全不出力。要检查角度对齐，必须引入**独立的信息源**
> ——比如 PMSM 模块内部记录的 dq 电流、或者反电势过零点。

## 问题11：某路示波器恒为 0

**现象**：`Scope4` 一直显示 0；`Scope5` 的三路信号里第三路也恒为 0。

**原因**：`PS-Simulink Converter4` 的**物理输入端是悬空的**
（模型里没有任何连线接到它），所以它的输出恒为 0，
而它被接到了 `Scope4` 和 `Scope5`。

**判定依据**：解包 `.slx` 读 XML 的物理连线，找不到任何以 `Converter4` 为端点的
`<Line LineType="Connection">`；而 `Scope4 ← PS-Simulink Converter4:0`。

**解决**：要看三相电流请用 **`Scope23`**（它接的是 Converter2/3/5 = i_a/i_b/i_c，是正确的）；
或者把 `PS-Simulink Converter4` 接到 `Current Sensor_ia3` 的 `I` 输出端口。

**教训**：原模型的 25 个 Scope 全是默认名（`Scope9`、`Display3`…），
调试前**先做一张"信号地图"**（哪个 Scope 看哪个信号），
否则很容易盯着一个恒为 0 的通道排查半天。

# 附录 A：本次用到的调试方法（可复用）

### A1. 编译检查比跑仿真快得多

改完模型先做一次编译检查，几秒钟就能发现连线/端口/采样时间问题，
不用等整个仿真跑完：

```matlab
set_param('PMSM_Model_fixed', 'SimulationCommand', 'update');
% ... 修改模型 ...
set_param('PMSM_Model_fixed', 'SimulationCommand', 'stop');
```

### A2. 不改模型结构，把任意信号引出到工作区

临时加一个 Outport 分支，仿真完再删掉，模型文件不会被改动：

```matlab
add_block('built-in/Outport', 'PMSM_Model_fixed/id_log', 'Port', '1');
add_line('PMSM_Model_fixed', 'Park Trans/1', 'id_log/1', 'autorouting', 'on');
out = sim('PMSM_Model_fixed', 'ReturnWorkspaceOutputs', 'on');
out.yout{1}.Values.Data
```

> 注意：在**函数内部**调用 `sim` 时，`To Workspace` 块写出的变量
> 不一定落在 base 工作区，用 `Outport` + `out.yout` 更可靠。

### A3. 把 Simscape 模块的内部量调出来 —— 最有价值的一招

```matlab
set_param('PMSM_Model_fixed', 'SimscapeLogType', 'all');
out = sim('PMSM_Model_fixed');
out.simlog.PMSM.i_d.series.values          % 模块内部真实 id
out.simlog.PMSM.i_q.series.values          % 模块内部真实 iq
out.simlog.PMSM.electrical_torque.series.values
out.simlog.PMSM.angular_position.series.values
```

模块内部的量是**独立于你的控制代码**的，用它来校准你的 Park 角度、
判断扭矩是否正常，比盯着示波器猜快得多。问题 10 就是靠这招定案的。

### A4. 用第二种实现交叉校验算法

不要用同一种思路验证自己。本次用"min/max 共模注入法"校验 SVPWM，
288 组工况一扫，立刻暴露 110 V 的误差（问题 7、8）。
**任何有解析答案的算法（SVPWM、Clarke/Park、坐标变换），都应该写一段离线脚本扫参数空间验证。**

### A5. 程序化读写 MATLAB Function 图表里的代码

```matlab
rt  = sfroot;
chs = rt.find('-isa','Stateflow.EMChart');
for i = 1:numel(chs)
    fprintf('%s : %s\n', chs(i).Name, chs(i).Path);
end
ch = chs(7);
disp(ch.Script);                 % 读
ch.Script = newText;             % 写
ch.ChartUpdate = 'DISCRETE';     % 设置离散执行
ch.SampleTime  = '1e-4';
```

> ⚠️ **两个必须注意的坑**：
> 1. 用普通字符串拼接写脚本时，`'\n'` **不会**被解释成换行，
>    会原样写进图表导致语法错误。要用 `sprintf`，或者用
>    `strjoin(每一行, char(10))` 来拼。
> 2. 用 `sprintf` 时**占位符数量必须和参数数量严格一致**。
>    数量不匹配时 MATLAB 不报错，但会生成残缺代码，
>    而 Stateflow 报出来的错误是"无法确定输出大小/采样类型"，
>    完全指不到真正的原因 —— 非常容易查错方向。
>
> 本次这两个坑各花了不少时间，建议直接用"逐行拼 `char(10)`"的写法。

# 附录 B：本次未触发、但容易踩的设计陷阱

### B1. 半桥不含续流二极管时，门极必须互补

本模型 `diode_param = include.no`，即半桥内部**没有反并联二极管**，
电流只能走 MOSFET 沟道。电机是强感性负载，电流不能突变，
所以**任何时刻都必须至少有一个管子导通**提供续流通路。
本模型用 `NOT` 生成互补门极（`Mux[上管, NOT 上管]`），既保证续流，又不会直通。

> 真实逆变器**一定有**反并联二极管（MOSFET 的体二极管）。
> 在 Simscape 里改成 `diode_param = include.yes` 更接近硬件。
> 另外真实硬件用互补门极时**必须加死区时间**，否则上下管换流瞬间会直通；
> 而死区会引入 6 倍电频率的电压畸变，这正是"死区补偿"要解决的问题。

### B2. SPS 的三角载波是双极性的，占空比是单极性的

`Triangle Generator`（SPS 库）内部实测：`1-D Lookup Table` 表值 `[0 2 0]`、
断点 `[0 0.5 1]`，配合 `rem(t·Freq, 1)` 产生 **−1 ~ +1** 的双极性三角波。
而 SVPWM 的 `Da/Db/Dc` 是 **0 ~ 1** 的单极性占空比，
所以必须经过 `Gain(×0.5)` + `Bias(+0.5)` 才能比较。
**换别家的三角波发生器时，一定要确认它的输出范围。**

### B3. `Ts = 1` 的归一化约定必须写注释

顶层 `Constant`（SID 64）值为 **1**，接到 `svpwm_time` 的 `Ts` 输入端。
因为 `Ta/Tb/Tc` 都是 `Ts` 的线性函数，令 `Ts = 1` 时
`Da/Db/Dc` **直接就是占空比**，可以拿去和归一化载波比较。
这是个实用技巧，但如果不在模型里写明，接手的人会以为 `Ts` 单位是秒而填 `1e-4`，
结果差 10000 倍。

### B4. 参数之间是联动的

```
Vdc = 100 V  →  SVPWM 线性区上限 Vdc/√3 = 57.7 V  →  PI 限幅取 57 V
             →  同时要改 svpwm_time 的 Vdc 输入（本模型通过 Constant1 送入）
```
**改母线电压时这几个地方必须一起改**，否则占空比计算整体缩放错。

### B5. Solver Configuration 的位置

本模型的 `Solver Configuration` 接在 **A 相回路上**（与 `PMSM` 的 a 相、
`Current Sensor_ia1` 同节点）。Simscape 只要求它接入物理网络、
不要求必须接地，所以仿真能正常跑；
但**工程习惯上大家都把它接在参考地节点**，读图时不容易困惑。

### B6. 两个电压传感器其实只测了母线电压

实测 `Voltage Sensor3` / `Voltage Sensor4` 的 `+` 都接直流母线 `+`、
`−` 都接母线 `−`，测的是**同一个母线电压**，而且控制算法里根本没有用到它们。
真正有价值的是**相电压/线电压**测量，用途是：① 无位置传感器控制的反电势观测；
② 死区补偿；③ 母线电压前馈。想练手可以把其中一个改接到相-中性点或线-线之间。
